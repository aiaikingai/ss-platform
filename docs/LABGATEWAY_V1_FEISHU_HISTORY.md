1. Labgateway Role in the Platform

Labgateway is the data publishing layer of the SS Lab Platform.

System architecture:

Lab Machines
   │
   ▼
Labtool
(MDB → CSV → Delta)
   │
   ▼
Labgateway
(Feishu API Publisher)
   │
   ▼
Feishu Sheets
   │
   ▼
Dashboards / analytics / alerts

Important design rule:

Local files = source of truth
Feishu = visualization layer

Feishu must never become the primary database.

6. Authentication Process

Feishu requires a tenant access token.

Token request endpoint:

POST /open-apis/auth/v3/tenant_access_token/internal

Request body:

{
  "app_id": "...",
  "app_secret": "..."
}

Response returns:

tenant_access_token
expire

Important discovery:

tenant_access_token expires

Therefore the system must:

refresh token automatically

8. Early API Attempts (Problems)

Early attempts used the following endpoint:

Sheets v2 batch_update API

Example usage:

batch_update

Problems encountered:

90204 errors
token failures

These problems occurred frequently.

9. Major Discovery: Feishu API Version Issue

The root cause was discovered:

Sheets v2 API is unreliable for certain operations

Specifically:

batch_update
sheet rename
spreadsheet rename

This caused repeated failures.

10. Final Working Solution

Correct API version discovered:

Feishu Sheets v3 API

Important endpoints:

Rename sheet
PATCH /open-apis/sheets/v3/spreadsheets/{spreadsheet_token}/sheets/{sheet_id}

Request example:

{
  "title": "NEW_NAME"
}
Rename spreadsheet
PATCH /open-apis/sheets/v3/spreadsheets/{spreadsheet_token}

Request:

{
  "title": "NEW_NAME"
}

This completely solved the 90204 errors.

This discovery is stored as a permanent rule:

Use Feishu Sheets v3 PATCH APIs
Avoid v2 batch_update

15. Performance Problem Discovered

Uploading full datasets repeatedly caused problems:

slow API performance
large uploads
duplicate rows

Conclusion:

incremental updates required

This reinforced the decision to implement:

delta architecture
16. Feishu Limitations Observed

Feishu Sheets limitations discovered:

• API rate limits
• large sheet performance issues
• rename API quirks in v2
• token expiration

These must be handled in Labgateway V2.

17. What Worked Successfully

The following components were successfully validated:

Feishu authentication
Feishu Sheets integration
Python API automation
Gateway computer architecture
Data publishing concept

The concept of the system is proven.

18. What Did NOT Work Well

V1 had several weaknesses.

No retry queue

If upload failed:

data loss possible
No upload cursor

System could not track:

which rows already uploaded
No delta support

Full dataset uploaded repeatedly.

Limited error logging

Failures were hard to diagnose.

19. Lessons Learned

Important conclusions from V1.

Use Feishu Sheets v3 API

Avoid v2 endpoints.

Token must refresh automatically

Authentication cannot be static.

Batch uploads required

Single-row uploads are inefficient.

Delta architecture necessary

Full dataset uploads are not scalable.
